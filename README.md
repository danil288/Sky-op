# CoopBridge: слежение за всеми NPC, управление ими и просмотр по сети

Плагин передаёт серверу **полные данные всех загруженных NPC** (здоровье, инвентарь, ИИ, бой, положение, фракции, эффекты…)
и обновляет их в реальном времени. В веб-панели список всех NPC; клик по строке открывает подробную карточку выбранного.
Ударили NPC в игре — здоровье на сервере меняется сразу (не позже чем через ~50 мс для выбранного и обычно в течение
~250 мс для остальных).
И наоборот: **любой изменяемый параметр можно поправить прямо в панели** (здоровье, характеристики, положение, инвентарь,
фракции, бой), и NPC в игре меняется. Постоянные данные (имя, ID, уровень, раса) не редактируются.

```
браузер ◄─ http://127.0.0.1:8777 ─► сервер (Node.js) ◄──TCP 127.0.0.1:7777──► плагин SKSE (C++) ──► все загруженные актёры
консоль ──► world on, watch 000A2C94                    ◄── state/gone: только изменения каждого актёра ──┘
```

В проекте две папки: `server/` (сервер) и `plugin/` (плагин для игры). Старые команды движения (`move`, `moveref`,
`stop`, `ping`) удалены вместе с кодом, который водил NPC. Игра теперь только отдаёт данные.

| Игровая часть плагина (`Watcher.cpp`, `Editor.cpp`, `main.cpp`) | **Не собиралась и не запускалась, нагрузку на игру не измеряли.** Её можно собрать только на Windows с игрой. Все вызовы CommonLibSSE-NG я сверил с заголовками тега `v12.1.0`, но первая сборка может показать мелкие ошибки: пришлите текст, я исправлю |

Что нужно посмотреть при первом запуске в игре:
- **Версия 1.7.104.** Библиотека явно поддерживает 1.7.99, а 1.7.104 — более позднее исправление той же ветки. Скорее всего, всё работает, но в игре я это не проверял.
- **Кодировка имён.** В вашей игре строки приходят уже в UTF-8, а плагин (`Text.cpp`) переводит их из cp1251 ещё раз, поэтому «Свен» превращается в «РЎРІРµРЅ». Пока плагин не менялся, сервер исправляет это сам (`server/src/text.ts`): распознаёт такие строки и возвращает нормальный вид. Это защита, а не лечение: правильное исправление надо сделать в плагине (убрать лишнюю перекодировку).
- **Некоторые поля могут быть пустыми:** `editorId` у пакетов ИИ (в обычной игре его нет), название локации и ячейки у части объектов.

**Чего нет:** переменные Papyrus-скриптов и состояние алиасов квестов (их нельзя перечислить без знания конкретных
скриптов), известные заклинания и перки, внутреннее состояние анимационного автомата Havok.

## Как это работает

Пока слежение включено, плагин каждые ~50 мс в основном потоке игры читает быстрые данные (показатели, положение, ИИ, бой)
и каждые ~250 мс медленные (инвентарь, фракции, эффекты, характеристики). Серверу уходят **только изменившиеся
разделы**. Если NPC стоит и ничего не меняется, по сети не идёт ничего. Обработчик ударов (`TESHitEvent`) дополнительно
запоминает, кто и чем ударил.

При переподключении к серверу плагин слежение сбрасывает: после перезапуска сервера введите `watch` снова.

## Игра вместе по сети (Radmin VPN, Hamachi)

Первый этап онлайна: **админ раздаёт данные своих NPC, остальные игроки видят их у себя в панели и, если админ разрешил, правят их.**
Игровой плагин для этого не менялся, обновляется только сервер. Выбор NPC, слежение за всеми и управление комнатой остаются у админа.

**Важно понимать, что происходит.** Мир это игра админа. Игрок видит данные NPC админа в своей панели, а его правки (здоровье,
инвентарь, положение, убить и воскресить, фракции, бой) отправляются админу и применяются **в игре админа**. В игре самого игрока
NPC не меняются: для этого нужен следующий этап («зеркало»: одинаковые сохранения и моды, отключение ИИ у повторяемых NPC, создание
NPC, появившихся во время игры).

**Права двух уровней.** Админ может всё. Игрок может только править NPC и только пока стоит галочка «Игрокам разрешено править NPC»
в карточке «Сеть» у админа; админ может снять её на ходу, игрок увидит это сразу («ИГРОК · только просмотр»). Игрок правит через те же
проверки, что и админ: постоянные данные (имя, ID, уровень, раса) изменить нельзя, частота команд ограничена (8 в секунду), изменения
записываются в журнал NPC с именем автора: «Изменено вручную (Вася): …».
Версии админа и игроков должны совпадать: комната проверяет версию протокола и при несовпадении пишет «обновите сервер».

**Radmin VPN** создаёт виртуальную локальную сеть: все, кто вошёл в одну сеть по имени и паролю, получают в ней адреса вида
`26.x.x.x` и видят друг друга, как в обычной локалке. Пробрасывать порты на роутере не нужно. Hamachi работает так же,
но в бесплатной версии пускает не больше 5 человек.

Как подключиться:

1. Все устанавливают Radmin VPN, один создаёт сеть, остальные входят в неё. Проверьте связь: `ping <адрес друга>` из командной строки.
2. **Админ** запускает сервер (`npm start`), в панели в карточке «Сеть» выбирает «Я админ», в поле адреса выбирает свой адрес в Radmin VPN
   (подсказки в поле; `0.0.0.0` значит «слушать во всех сетях»), оставляет порт 7788, придумывает пароль (от 4 символов) и нажимает
   «Запустить комнату». Игрокам сообщает адрес, порт и пароль.
3. **Каждый игрок** запускает свой сервер (`npm start`), в панели выбирает «Я игрок», вводит адрес админа, порт, пароль, своё имя и
   нажимает «Подключиться». В шапке появится «ИГРОК · только просмотр», в списке будут NPC админа.
4. **Брандмауэр Windows.** При первом запуске комнаты Windows спросит разрешение для Node.js. Разрешите, причём для сети, которую
   Windows считает общедоступной: сеть Radmin VPN обычно попадает именно туда. Если игроки не могут подключиться, а `ping` проходит,
   причина почти всегда в брандмауэре.

Что делает защиту: комната закрыта паролем (по сети передаётся не сам пароль, а подпись от него); после 5 неудачных попыток адрес
блокируется на минуту; подключиться можно не более чем 8 игрокам; «замолчавшие» игроки отключаются; при обрыве игрок
переподключается сам и получает свежий снимок. Пароль нигде не сохраняется, а в браузере запоминаются только режим, адрес, порт и имя.

Что не делается пока: NPC в игре у остальных игроков не меняются (то есть изменения админа видны игроку в панели, но не в его игре) (нужны одинаковые сохранения и моды, отключение их ИИ и создание
двойников), урон и действия остальных игроков не доходят до админа, игроки друг друга не видят. Это следующие этапы.

## Слежение за всеми NPC

При подключении игры сервер сам включает слежение за всеми загруженными актёрами (кнопка «Слежение за всеми» в панели,
команда `world on|off` в консоли, переменная `BRIDGE_TRACK_ALL=0` отключает автовключение). В список попадают все, кто
сейчас есть в мире рядом с игроком: жители, враги, животные, мёртвые тела и сам игрок. Когда персонаж выгружается из мира
или появляется, список обновляется сам.

Что видно в панели: список с поиском, сортировкой (по расстоянию до игрока, по имени, по здоровью) и фильтром «скрыть
мёртвых». Расстояние показывается в метрах (70 единиц игры = 1 м) и только если NPC и игрок в одной ячейке. Клик по строке
выбирает NPC: открывается его подробная карточка, а плагин начинает читать его каждый такт. Редактировать можно любого
NPC из списка (сначала выберите его).

**Как это не убивает частоту кадров.** Плагин не читает всех подряд каждый такт. Выбранный NPC читается каждые ~50 мс.
Остальные идут по очереди: быстрые данные каждого (показатели, положение, ИИ, бой) обновляются раз в `FastMs`, медленные
(инвентарь, фракции, эффекты, характеристики) раз в `SlowMs`, но суммарно не дольше `BudgetMs` за такт. Если актёров
много, очередь просто растягивается, а игра не получает лишней нагрузки. Тот, по кому ударили, читается вне очереди, чтобы
удар был виден сразу. Серверу уходят только изменившиеся разделы, поэтому стоящий NPC почти ничего не передаёт.

Настройки в `CoopBridge.ini` (раздел `[World]`):

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `MaxActors` | 300 | сколько ближайших к игроку актёров отслеживать |
| `BudgetMs` | 2 | сколько миллисекунд за такт можно тратить на чтение |
| `FastMs` | 250 | как часто перечитывать быстрые данные каждого NPC |
| `SlowMs` | 1000 | как часто перечитывать медленные данные |

Если игра подтормаживает, уменьшите `MaxActors` или `BudgetMs`, либо увеличьте `FastMs` и `SlowMs`. В журнале плагина при
запуске пишутся действующие значения. Реальную нагрузку я измерить не мог, поэтому значения по умолчанию осторожные.

**Важно знать:** refID зависит от порядка загрузки модов. На одном компьютере это не мешает. Если позже понадобится
сопоставлять NPC между двумя компьютерами с разными сборками, потребуется другой идентификатор (мод и локальный номер).

## Изменение параметров

В веб-панели поля ввода у показателей, характеристик и координат редактируются так: измените число и нажмите Enter
(Esc отменяет). Результат виден сразу, потому что панель показывает не то, что отправили, а то, что реально стало в игре.
Если игра не приняла значение или пересчитала его иначе, об этом написано в сообщении под строкой слежения.
Панель заблокирована, пока NPC не выбран или игра не подключена.

| Что | Как менять |
|---|---|
| Здоровье, магия, выносливость | поля «текущее», «максимум», «база», «пост. модификатор», «врем. модификатор», «урон». «Текущее» правит урон; выше максимума поднять нельзя; здоровье меньше 1 не принимается (для смерти есть «Убить») |
| Характеристики | агрессия, уверенность, энергия, мораль, настроение, помощь, скорость %, грузоподъёмность, скорости регенерации, паралич, невидимость. «Вес вещей» считает игра, его менять нельзя |
| Положение | x, y, z и угол: телепорт в пределах загруженной ячейки |
| Действия | убить, воскресить, достать и убрать оружие, начать бой с указанной целью (FormID или `player`), прекратить бой |
| Фракции | добавить с рангом, изменить ранг, удалить (✕ у фракции) |
| Инвентарь | добавить и убрать предмет по FormID, кнопки «−1», «убрать все», «надеть» и «снять» у каждой строки |

**Что изменить нельзя** (постоянные данные записи или служебные значения): имя, FormID и baseID, уровень, раса, флаги
«неубиваемый» и «защищённый», вес вещей, пакет ИИ и поза, последний удар, служебные данные. Этих полей нет в списке
допустимых ни на сервере, ни в плагине.

**Пока не реализовано:** эффекты (наложить и снять), флаг «спутник игрока» (в этой версии библиотеки нет безопасного
вызова), задачи ИИ вроде «идти в точку» или «сесть».

То же командами в консоли для выбранного NPC (`watch <refID>`; FormID пишите восемью цифрами, чтобы его не приняли за количество):

```
set vitals.health.current 50
set inventory.add 3 0003133C        # количество, затем FormID предмета
set faction.add 2 0005C84D          # ранг, затем FormID фракции
set action.startCombat player
set action.kill
```

Защита: плагин меняет **только тех NPC, которых сейчас отслеживает** (есть в списке загруженных или выбран), и проверяет каждое значение ещё раз после сервера.
Сервер принимает команды панели только с ключом, который создаётся при каждом запуске и вставляется в страницу. Обновляйте
страницу после перезапуска сервера.

**Осторожно:** правки попадают в сохранение (урон, инвентарь, фракции, ранги), поэтому пробуйте на отдельном сохранении.
Игра сама перезаписывает часть значений: здоровье начнёт восстанавливаться, эффекты и пакеты ИИ пересчитывают данные.
Общие записи (например, все стражники) правка экземпляра не затрагивает.

## Что нужно установить

Для игры:
- Skyrim с обновлением 1.7.104 (у вас такая версия).
- SKSE64 для вашей версии (для 1.7.104 это 2.3.1) с сайта skse.silverlock.org.
- Address Library for SKSE Plugins с Nexus. В `Data\SKSE\Plugins` должен лежать файл `versionlib-...bin` под вашу версию игры.
- Игру нужно запускать через `skse64_loader.exe`.

Для сборки:
- Node.js 20 или новее.
- Visual Studio 2022 или Build Tools с набором «Разработка классических приложений на C++».
- Git.
- xmake версии 3.0.0 или новее (xmake.io).

## Запуск сервера

```
cd server
npm install
npm run build
npm start
```

При запуске сервер печатает адрес веб-панели (по умолчанию `http://127.0.0.1:8777/`) и сам открывает её в браузере.
Игра подключается к `127.0.0.1:7777`. Версия плагина и протокола изменилась (0.4.0, протокол 4): **пересоберите и плагин, и сервер**. Оба порта слушаются только на локальном адресе.

| Переменная | Что меняет |
|---|---|
| `BRIDGE_PORT` | порт для игры (по умолчанию 7777) |
| `BRIDGE_UI_PORT` | порт веб-панели (по умолчанию 8777) |
| `BRIDGE_UI_OPEN=0` | не открывать браузер автоматически |
| `BRIDGE_UI=0` | выключить веб-панель совсем (останется консоль) |
| `BRIDGE_TRACK_ALL=0` | не включать слежение за всеми автоматически |
| `BRIDGE_CONSOLE_PANEL=1` | вернуть старую консольную панель с перерисовкой экрана (она мигает) |

## Веб-панель

Страница показывает те же данные, что и раньше консоль, но обновляет только изменившиеся значения, поэтому ничего не мигает:
показатели с полосками и подсветкой при ударе, положение, ИИ и бой, характеристики, фракции, эффекты, последний удар,
журнал изменений и инвентарь таблицей. Сверху поле для refID и кнопки «Следить», «Игрок» (следить за игроком) и «Стоп».
Можно открыть панель в нескольких вкладках: все показывают одно и то же.

В консоли остались те же команды и короткие строки журнала («08:25:27 Здоровье: 100.0 → 93.0 (−7.0)»).

Безопасность панели: она слушает только `127.0.0.1`, проверяет заголовки `Host` и `Origin` (чужие сайты в браузере не смогут
ею управлять) и принимает команды только как `application/json`.

**Проверка без игры.** В другом окне запустите `npm run mock`: имитатор подключится как плагин, а после «Следить» с любым
refID будет раз в 3 секунды «бить» выдуманного NPC. Видно, как панель обновляется сама.

## Сборка плагина

Библиотеку подключаем рядом с проектом, лучше с фиксированной версией:

```
cd plugin
git init
git clone --recurse-submodules --branch v12.1.0 https://github.com/alandtse/CommonLibSSE-NG.git lib/commonlibsse-ng
xmake f -m releasedbg -y
xmake build
```

Готовую `CoopBridge.dll` ищите в папке `plugin\build\` (обычно `build\windows\x64\releasedbg\`). Скопируйте её в
`Data\SKSE\Plugins` игры. Файл `CoopBridge.ini` из папки `plugin` нужен только если сервер не на `127.0.0.1:7777`.

Чтобы xmake копировал плагин сам, задайте переменную среды `XSE_TES5_GAME_PATH` (папка Skyrim) и выполняйте `xmake install`.

## Как пользоваться

1. Запустите сервер (`npm start`). Порядок не важен: плагин переподключается каждые 2 секунды.
2. Запустите игру через `skse64_loader.exe` и загрузите сохранение. В консоли сервера появится «игра подключена».
3. Узнайте refID персонажа: откройте консоль игры клавишей `~` и кликните мышью по NPC. Наверху консоли появится его
   номер в скобках, например `000A2C94`.
4. В веб-панели выберите NPC в списке (или введите refID). То же в консоли сервера:

| Команда | Что делает |
|---|---|
| `world on` / `world off` | слежение за всеми загруженными NPC |
| `list` | показать отслеживаемых NPC |
| `watch 000A2C94` | выбрать NPC: читается каждый такт, его журнал печатается в консоль. Вместо refID можно написать `player` |
| `watch off` | снять выбор |
| `set <поле> …` | изменить параметр выбранного NPC |
| `help`, `quit` | служебные |

Журнал плагина: `Documents\My Games\Skyrim Special Edition\SKSE\CoopBridge.log`.

## Ограничения

- **NPC должен быть загружен** (рядом с игроком). Если он выгружен из мира, панель покажет «НЕ ЗАГРУЖЕН В МИР» и последние известные данные.
- **Сервер не защищён**: он слушает только локальный адрес и не проверяет, кто подключился. Для игры по сети понадобятся адрес, шифрование и авторизация.
- **Лицензия.** CommonLibSSE-NG распространяется под GPL-3.0-or-later (с исключениями для модов). Плагин статически подключает её, поэтому при передаче DLL другим людям нужно передавать и исходники.

## Устройство

| Файл | Назначение |
|---|---|
| `server/src/protocol.ts` | формат сообщений (в комментарии в начале файла) |
| `server/src/bridge.ts` | TCP-сервер, команды, приём `state`, таймауты, обрыв связи |
| `server/src/npc.ts` | состояние NPC, журнал изменений, отрисовка панели |
| `server/src/hub.ts` | комната админа: приём игроков, проверка пароля, рассылка событий, защита от перебора |
| `server/src/viewer.ts` | подключение игрока к комнате админа, переподключение |
| `server/src/remote.ts` | копия мира админа на стороне игрока (для новых вкладок браузера) |
| `server/src/net-config.ts` | проверка настроек сети, список адресов компьютера |
| `server/src/world.ts` | реестр всех отслеживаемых NPC на сервере (данные и журнал каждого) |
| `server/src/edit.ts` | список допустимых правок и проверка значений (форма и диапазон) |
| `server/src/ui.ts` | веб-сервер панели: страница, поток событий (SSE), команды, проверка Host/Origin |
| `server/ui/index.html` | страница веб-панели |
| `server/src/text.ts` | исправление дважды перекодированного текста (временная защита, пока плагин не исправлен) |
| `server/src/index.ts` | запуск, консоль (`watch`), связь панели с игрой |
| `server/tools/mock-plugin.mjs` | имитатор плагина для проверки без игры |
| `plugin/src/Protocol.cpp` | разбор команд `watch` / `unwatch` и формирование ответов (без зависимости от Skyrim) |
| `plugin/src/Json.h` | писатель вложенного JSON |
| `plugin/src/State.h` | выбор изменившихся разделов и сборка сообщения `state` |
| `plugin/src/Text.cpp` | перевод строк игры из ANSI в UTF-8 |
| `plugin/src/Net.cpp` | сетевой клиент в отдельном потоке с переподключением |
| `plugin/src/Registry.h` | реестр отслеживаемых актёров и планировщик опроса по очереди (без зависимости от Skyrim) |
| `plugin/src/Watcher.cpp` | список загруженных актёров, чтение данных, таймер, обработчик ударов, приём команд |
| `plugin/src/Editor.cpp` | применение правок (команда `set`) к NPC в игре, итоговая проверка значений |
| `plugin/src/main.cpp` | точка входа SKSE, подключение всего вместе |
